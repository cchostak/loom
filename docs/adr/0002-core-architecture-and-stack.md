# ADR 0002: Core Architecture, Gateway Protocols & Security Boundaries

## Status
**Accepted**

## Date
2026-08-29

## Context & Problem Statement
Modern cloud development environments require seamless access to Large Language Models (LLMs) and Model Context Protocol (MCP) toolkits (filesystem access, web search, code analyzers). However, granting direct LLM access and unrestricted tool invocation inside developer workspaces introduces severe security risks:
1. **Destructive Command Execution**: AI models may generate or execute dangerous shell commands (`sudo`, `rm -rf /`, fork bombs, disk overwrites).
2. **Unauthorized Tool Access**: MCP tools may allow unrestricted filesystem tampering or arbitrary network egress.
3. **Lack of Observability**: LLM token consumption, latency spikes, and tool invocation failures are invisible without centralized telemetry.

We need a unified, containerized stack that enforces pre-execution guardrails, enforces strict MCP tool authorization, and provides end-to-end distributed tracing.

## Decision Outcome
We have chosen the following architectural components and patterns:

### 1. Unified Gateway Proxy (`Agentgateway`)
- **Role**: Serves as the single ingress point for all LLM and MCP requests generated by the Web IDE.
- **Port 8080**: OpenAI-compatible `/v1` endpoint routing upstream to OpenRouter.
- **Port 3000**: Model Context Protocol (MCP) server gateway managing stdio tool processes (filesystem, Brave Search).
- **Rationale**: Decouples IDE extensions from proprietary provider APIs and centralizes policy enforcement.

### 2. Synchronous Pre-Execution Guardrail Proxy (`guardrail-proxy`)
- **Role**: High-throughput Go microservice running on port 9090.
- **Mechanism**: Agentgateway sends normalized content to `/request` before model dispatch and `/response` before returning model output. The webhook returns a Guardrail API `PassAction` or `RejectAction`.
- **Policy Enforcement**:
  - Sub-millisecond string and regex inspection for high-risk commands (`sudo`, `rm -rf`, `chmod 777`, `mkfs`, fork bombs, `/etc/shadow`, `/etc/passwd`).
  - Returns `403 Forbidden` with a list of matched patterns if forbidden content is found.
  - Fail-closed configuration (`blockOnError: true`) prevents prompt leakage on validator downtime.
- **Rationale**: Go provides minimal memory footprint (<20MB) and sub-millisecond execution times under concurrent load.

### 3. CEL-Based MCP Tool Authorization
- **Role**: Common Expression Language (CEL) policy engine embedded in Agentgateway.
- **Rule**: MCP authorization is allow-list based; unmatched tools are denied and filtered from discovery.
- **Allowlist**:
  ```cel
  mcp.tool.name == "read_text_file" || mcp.tool.name == "list_directory" || mcp.tool.name == "search_files"
  ```
- **Rationale**: Prevents prompt injection attacks from triggering destructive filesystem writes or arbitrary code execution tools.

### 4. End-to-End Distributed Tracing (`OpenTelemetry + Jaeger`)
- **Role**: Centralized OTLP gRPC telemetry pipeline.
- **Flow**: Agentgateway emits OTel trace spans for every LLM completion and MCP tool invocation -> OpenTelemetry Collector Contrib (port 4317/4318) -> Jaeger UI (port 16686).
- **Rationale**: Gives platform engineers and developers instant visibility into token counts, latency breakdowns, and tool invocation call graphs.

### 5. Network Isolation (`ide-net`)
- **Role**: Private Docker bridge network.
- **Security Boundary**: Containers communicate over private DNS (`agentgateway:8080`, `guardrail-proxy:9090`, `jaeger:4317`, `otel-collector:4317`). Only necessary ports are bound to `localhost`.

## Consequences
* **Positive**:
  * Guaranteed pre-execution filtering of destructive AI suggestions.
  * Deterministic, declarative tool authorization using CEL.
  * Comprehensive trace visibility across all model interactions.
  * Fully containerized and reproducible with `docker compose up -d`.
* **Trade-offs**:
  * Added latency of ~1-3ms per prompt for synchronous guardrail validation (negligible compared to LLM generation time).
  * Requires maintaining the forbidden pattern list and CEL tool allowlists.
